# Managed Connections (RBAC) — Design & Threat Model

> **Status: shipped.** This document describes managed mode as built. For the mechanics see
> [architecture.md](architecture.md) (§ Managed Connections) and for running it see
> [deployment.md](deployment.md) (§ Managed mode). An earlier external-repo / capability-proxy
> design was considered and rejected; this is the design that shipped.

## What it is

The default app is a pure browser tool: the user types broker SMF + SEMP credentials into the
`connections` module and the browser connects directly. **Managed mode** is for users who must NOT
hold broker credentials. The same `connections` module offers a second tab: the user logs in, picks
from the **brokers and Message VPNs they are entitled to**, and the broker credentials are fetched
(still obfuscated) and unpacked client-side just-in-time. Two admin-only modules
(`user-management`, `connection-management`) manage the entitlement data.

**It is a runtime posture, not a build.** Every bundle carries both paths; which tabs the app offers
is decided by the gateway's `/hosted` response (`CONN_MODES` / `DEFAULT_CONN` — see
[deployment.md](deployment.md)). With no gateway there is no `/hosted`, so Managed never appears.
Managed mode only works behind the [go-web-proxy](../go-web-proxy) in `MANAGED=true HOSTED=true`
mode. There is no longer a separate `managed` variant: a managed deployment ships the standard bundle. The entitlement editors live in their own `admin` variant, served at `/solAdmin` (see [architecture.md](architecture.md) — The admin app).

## Topology

```text
 Browser (any bundle, served by go-web-proxy in managed mode)
   connections ── Managed tab: login → POST /managed/getConnections {username, token}
        └─ profile (incl. site seed) → core managed session store; on Connect the store unpacks
           the entitled broker creds just-in-time and dials via the gateway
   queue-browser ── unchanged; uses the entitlement-filtered queue-picker + the guardrailed session
   queue-copy ── source filtered as above; destination may reuse the SAME provisioned credentials
   (administration is a SEPARATE app at /solAdmin: admin-login + user-management +
    connection-management, POSTing /managed/{listUsers,saveUser,...}. It authenticates
    against the same user list but opens NO broker connection.)
        │ broker traffic + /managed/* → same origin
        ▼
 go-web-proxy (MANAGED mode — performs NO cryptography)
   /hosted {hosted, connModes, defaultConn}, SPA, transparent broker reverse-proxy (relay ungated)
   + loads users + connections YAML (RWMutex); bootstraps a default admin if absent;
     generates a per-deployment site-seed file if absent
   + POST /managed/getConnections → string-match auth → entitled brokers/VPNs + queue globs
   + POST /managed/reload → re-read both YAML files from disk (any logged-in user)
   + /managed/{users,connections} CRUD (admin-only; resend-token auth)
        ▼
 Solace broker (SEMP + SMF/WebSocket) — use a READ-ONLY / least-privilege SEMP account
```

## Locked decisions

- **Enforcement = proxy connection-gating + client guardrails only.** The proxy returns only the
  entitled connections plus per-queue permission globs; the client filters discovery and guardrails
  the UI. **The broker relay stays ungated** (see Threat model).
- **The proxy performs zero cryptography.** The client↔proxy channel always carries the
  already-transformed credential string; authentication is a **string match**, never a decrypt.
- **Admin CRUD authenticates by resend-token** — each admin call re-sends the admin `username`+`token`
  (held in memory in `AppState.managed`). This is a deliberate non-standard choice, accepted because
  it is confined to a handful of admin-only endpoints with no session layer.
- **Credential model = two client-side values.** A one-way, deterministic **login token** derived
  from the username and password (used for string-match login and stored in the users file, so the
  same pair always yields the same token and no two users share one), and a per-deployment **site
  seed** (random bytes generated by the proxy on first run, served post-auth, imported
  non-extractable, used to obfuscate/reveal broker credentials). This is **obfuscation**: it raises
  effort and protects a *leaked YAML file from offline reversal*; it gives no confidentiality against
  a legitimately entitled user. The transform is **versioned and swappable**, and its algorithm is
  **intentionally not documented** (code-only).
- **Bootstrap admin.** If the users file is missing, the proxy writes a default admin (`admin` /
  `msgutility`, no broker access). **Change this password immediately via User Management** — the
  default is public in this repo.
- **RBAC semantics.** `operate ⊇ read-only`; dropdowns show the union. Globs are **case-sensitive**
  and support multiple / leading / middle / trailing `*`. A row matches only when its `brokers` AND
  `msgVpns` AND `queues` all match the currently-connected broker + VPN + candidate queue. The
  matchers live in [src/core/rbac.ts](../src/core/rbac.ts) (`matchGlob`, `isModuleVisible`,
  `isVpnVisible`, `isQueueVisible`, `canOperate`) and are mirrored in the proxy's `rbac.go`, pinned by
  a shared conformance vector.
- **Admin modules are gated by `admin: true`** via `isModuleVisible` (the kernel re-renders the
  sidebar on `rbac:changed`).
- **Connection posture is one enum.** `CONN_MODES` (`direct` | `managed` | `both`) plus
  `DEFAULT_CONN` reach the app through `/hosted`; `resolveConnTabs` turns them into the tab list and
  `resolveDestCredModes` derives what a *secondary* connection may offer. One source of truth, so the
  primary's tabs and a module's secondary credential options cannot drift apart. No `/hosted` ⇒
  Direct only, always.
- **Managed is a convenience unless the deployment makes it exclusive.** Under `CONN_MODES=both` a
  user may simply switch to the Direct tab and type any credentials they happen to know — every
  entitlement guarantee in this document holds **only** under `CONN_MODES=managed`. `both` is
  supported deliberately (mixed audiences), and is a documented bypass, not an oversight.
- **Credential-bearing state is core-owned and injected.** The provisioned profile and the site seed
  live only in [managed-session-store.ts](../src/core/services/managed-session-store.ts), reached via
  `AppContext.managedStore`. `AppState.managed` carries **matcher inputs only** (names, globs, the
  login token). Callers ask the store to *dial a target they name*; they never receive a credential,
  and cannot enumerate one. This is what lets a second module (queue-copy) open a provisioned
  connection without importing the connections module and without credential-bearing globals.
- **Modules that cannot be filtered are hidden, not trusted.** `MODULE_REQUIREMENTS` in
  [rbac.ts](../src/core/rbac.ts) marks `queue-subscription-explorer` and `queue-discovery` as
  requiring unfiltered SEMP; both are hidden in **every** managed session, admin included, because
  they read over SEMP v1 RPC which the discovery filter does not rewrite (see Threat model).
- **Writes are gated where they happen.** Copying *into* a queue is a write, so queue-copy's
  destination picker lists at `operate` scope and a final destination gate refuses a target the user
  cannot operate on. **Topic destinations are refused on any provisioned publish path** — entitlements
  are expressed per queue and a topic fans out to every queue subscribed to it, so it cannot be
  checked. It is refused rather than guessed.

## Threat model (honest, documented)

- The broker **relay is ungated** — only `/managed/*` is gated. An entitled user who captures their
  own relayed credentials can exceed their queue-glob entitlement on reachable brokers. The
  client-side queue/read-only guardrails are therefore **UX, not a security boundary**.
- **`CONN_MODES=both` is a full bypass** of everything in this document: the Direct tab accepts any
  credentials the user can supply. Deployments that need the entitlement model to *hold* must set
  `CONN_MODES=managed`.
- **The filter is per-transport, not per-capability.** `filterSempFetch` rewrites exactly two SEMP
  **v2 monitor list** shapes. Every **SEMP v1 RPC** (`POST /SEMP`), every single-object GET, and every
  non-JSON response passes through untouched. Any code path that reaches the broker another way is
  unprotected by construction. Two consequences are handled explicitly, and the pattern is the thing
  to remember when adding features:
  - `queue-subscription-explorer` / `queue-discovery` read only over v1 RPC ⇒ **hidden** in managed
    sessions rather than shipped unfiltered.
  - queue-copy's verify also uses v1 RPC ⇒ a **source gate** refuses a non-entitled queue *before*
    the probe is spawned, so a managed user cannot type an arbitrary queue name and read back its
    depth, size and message IDs.
- The **site seed is shared across users** and traverses the wire, so it is recoverable by any
  entitled user. Its real value: a stolen connections file cannot be reversed offline without also
  compromising a session or the key file.
- The **credential transform now ships in every bundle** (it did not before, when managed code was
  excluded from non-managed builds by non-import). It was always present in *managed* bundles and
  always recoverable by an entitled user, so this changes the **breadth** of exposure, not its kind —
  but the build-level separation, and the isolation grep that enforced it, are gone by design.
  `scripts/check-docs-secrecy.mjs` guards only against *documenting* the construction.
- The **login token is a bearer credential**; reading the users file yields replayable bearers.
  Mitigations: filesystem permissions + TLS. (The admin CRUD list endpoints never return stored
  tokens or packed broker secrets back to the client.)
- **Required mitigation:** configure per-broker **read-only / least-privilege SEMP accounts** (never
  broker-admin) so a captured credential's blast radius is bounded. Managed mode is fit for
  **trusted-internal** use only.

## YAML schemas (managed by the admin modules; never hand-edit in production)

```yaml
# users.yaml
msg-utility-users:
  - username: admin
    password: <login-token>      # client-computed; the proxy string-matches, never reverses
    admin: true
    operate:   [{ brokers: '*', msgVpns: vpn1, queues: queue1 }]
    read-only: [{ brokers: '*', msgVpns: '*',  queues: '*' }]
# connections.yaml  (use a READ-ONLY SEMP account)
msg-utility-connections:
  - broker: broker-name
    hostname: www.example.com
    semp:   { port: 1943, username: monitor, password: <obfuscated> }   # client-side, opaque to proxy
    client: { port: 1443, msgVpns: [ { name: vpn-name, username: default, password: <obfuscated> } ] }
```
